DAY 23 / MOVEMENT 03

Calling functions in a meaningful order

Coordinate a small sequence of function calls with visible dependencies, bounded retries and a meaningful human handover.

In this guide

PurposeWorked exampleStudio stepsTeaching and evidenceReview and accessOriginal readingNext stepPractical resources ↗

Expanded studio guide · 28 October 2026

What you will practise

Coordinate a small sequence of function calls with visible dependencies, bounded retries and a meaningful human handover.

A caller needs to know what each function consumes, returns and changes. The source’s scenario-based sequencing becomes concrete when one output can be traced into the next input. Distinguish independent work from work waiting on an answer. A failed lookup should not become an invented result simply to keep the sequence moving. Use a diagram, paper rehearsal or local demonstration to represent the proposed caller and label its actual implementation state. The learner approves any outward action.

A worked example

Illustrative example: a fictional workshop pack requires an approved room note and an equipment inventory. These two lookups can happen independently. Drafting a session depends on both and on the audience brief. Saving a private draft follows a completeness check; sending invitations is outside scope. When the room note is unavailable, the caller may prepare an explicitly provisional activity outline but must return the unresolved venue question.

Make, test and revise

  1. Draw five function cards and arrows showing the exact output used by each later step. Mark the two independent lookups and the point at which human review is required.
  2. Run the complete case, recording call order, input references and returned status. Check that the saved draft corresponds to the same source versions reviewed by the learner.
  3. Remove the room note and impose a maximum of one retry. Rehearse the partial-result route, recording which sections can proceed and the question handed to the venue organiser.
  4. Introduce conflicting equipment records. Require the caller to retain both sources and seek clarification, then ask a peer to reconstruct the sequence from its trace.

Teach it to another adult

Use a familiar meal or performance preparation to explain dependencies. Have the newcomer rearrange the cards and point to a step that cannot honestly begin yet.

Keep evidence someone can inspect

  • A call map distinguishing independent work, dependencies and human review.
  • Three scenario traces with statuses and a visible retry limit.
  • A handover stating completed work, conflicting evidence and the responsible next contact.

Try a changed condition

Replace the workshop with a short field-observation project and make its weather note unavailable. Ask the peer to design an honest partial result and explain what would justify continuing.

Reflect on the result

  • Which step would use stale information if the audience changed?
  • Can the trace explain why a call occurred at that time?
  • Where does the process stop instead of repeatedly asking the same failing service?

Adapt the encounter

Offer numbered cards, a spoken walkthrough and an uncluttered dependency diagram. Let the learner control the pace and keep the current state visible throughout the rehearsal.

Take it further

Compare sequential and independent execution of the two lookups using recorded demonstration timings. Discuss the coordination benefit without presenting simulated timings as a production performance claim.

The original daily reading

Preserved reading from the 14 October 2026 course, PDF page 23. The studio guide above adds practical detail; it does not replace this source.

A Function Caller selects an available function and supplies the information needed for it to work. Today's objective is to make the order of calls understandable and evaluate whether the resulting sequence serves the learner's purpose. The class uses yesterday's functions in a small scenario with several dependent steps.

The scenario might prepare a community workshop. The caller retrieves relevant sources, identifies the adult audience, drafts a lesson, checks the planned activity and saves the result for review. Each step receives a clear input and returns something the next step uses. A changing condition, such as an unavailable room or revised audience, affects the sequence visibly.

The studio task draws a call map and then rehearses it. The learner identifies independent steps, dependent steps, review points and an end condition. A technical builder implements the map in a practice environment. Other learners inspect whether the order makes sense, whether a question appears at the right time and whether the final result matches the original purpose.

The source papers describe scenario-based sequencing, role training, integration tests and periodic refinement. The course develops those proposals through observable calls and results. A function name alone is insufficient context for the learner; the interface also shows its purpose, required information, current permission and expected effect. [S09, pp. 20-24]

Three tests introduce increasing difficulty. A complete scenario tests the normal path. An unavailable resource tests an alternative route. Conflicting source material tests the review and handover. The caller receives a visible limit on retries and a defined way to return an unresolved question to the learner. The event history records which functions were used and why.

The reflection compares the caller's sequence with the way the person organises a day. Some actions depend on preparation; others proceed in parallel; some need a conversation before a decision. The learner identifies an ordinary routine they would like an Aura to help coordinate and records where human judgement enters.

Teaching practice explains the call map to a newcomer using a familiar activity, such as planning a meal or preparing a creative performance. The newcomer rearranges a small set of action cards and identifies a missing input. The trainee uses that encounter to improve the interface labels.

Evidence includes the call map, function records, three scenario traces, retry and handover behaviour, and the learner's review. The capability built today is coordination with a readable purpose. It prepares the next lesson, where different specialist agents contribute distinct knowledge and methods to the same task.

Source: S09 Mixture of Experts Function Callers and AutoGen Agents.
