DAY 22 / MOVEMENT 03

Discovering and defining a function

Turn a personally meaningful wish into a versioned function definition with testable inputs, outputs and behaviour when information is missing.

In this guide

PurposeWorked exampleStudio stepsTeaching and evidenceReview and accessOriginal readingNext stepPractical resources ↗

Expanded studio guide · 28 October 2026

What you will practise

Turn a personally meaningful wish into a versioned function definition with testable inputs, outputs and behaviour when information is missing.

Function discovery begins by returning the person’s purpose in their own words. A Function Definer is a proposed role in the source architecture, not authority to decide what the person ought to want. Today’s record makes one capability specific enough for a caller to request tomorrow. Describe input fields before choosing a software format; a schema can initially be a table. Treat factual sources, learner preferences and inferred conveniences differently. The human owner approves the boundary between assistance and a judgement they retain.

A worked example

Illustrative example: Priya wants help preparing a short introduction to community sound recording. Her practice function, prepare_session, receives a topic, selected sources, adult audience, time available, access preferences and output format. It returns a draft sequence, one practical task and unresolved questions. It does not enrol learners, assess hearing or grant recording permissions. An absent time budget produces a clarification request.

Make, test and revise

  1. Hold a discovery conversation and write a one-sentence purpose Priya recognises. Name the decision she wants assistance with and one choice she wants to make herself.
  2. Create version 0.1 with fields for owner, purpose, inputs, outputs, permitted data, side effects, review, version and evidence. Give every required field an example and a missing-value rule.
  3. Try a familiar topic, an unfamiliar topic with supplied sources and a conflict between a ten-minute limit and a long activity. Use a paper rehearsal or a small local demonstration.
  4. Compare results with Priya’s purpose. Revise one ambiguous field, record the reason in version 0.2 and rerun the failed case before describing the definition as improved.

Teach it to another adult

Help another adult define a function for their own interest. Explain the service through a worked exchange before introducing schema terminology, then ask them to challenge one boundary.

Keep evidence someone can inspect

  • Discovery notes preserving the learner’s wording and retained judgement.
  • A versioned function record with sample inputs and expected outputs.
  • Three test records and a comparison showing the effect of one revision.

Try a changed condition

Give the function to a peer planning a different creative activity. They must identify which fields still work, which need a new example and where subject-specific permission remains unresolved.

Reflect on the result

  • Would two callers interpret each required field the same way?
  • What does the function return when sources do not support the requested detail?
  • Which improvement came from understanding the person rather than adding automation?

Adapt the encounter

Allow the definition to begin as a conversation, illustrated table or card set. A builder can translate the agreed record into code while the owner reviews its examples.

Take it further

Define a deliberately narrower companion function that only checks whether a session brief is complete. Compare its acceptance evidence with that of the drafting function.

The original daily reading

Preserved reading from the 14 October 2026 course, PDF page 22. The studio guide above adds practical detail; it does not replace this source.

A function gives a desired capability a specific form. Today's objective is to move from an ordinary-language wish to a testable exchange with defined inputs and outputs. The learner works with an Aura acting as a Function Definer, exploring what the person actually wants before the capability is delegated.

The source agent paper makes this discovery explicit. The human and Function Definer work with each agent to generate its functions. The functions are refined, then other models learn how to select and order them in scenarios. This sequence places meaning and purpose before automation. [S09, pp. 20-24]

The learner chooses a service such as preparing a teaching session from selected records. They describe who it serves, what useful completion looks like and which context affects the result. The discovery conversation asks about audience, available time, pacing, source material, tools, output format and review. A worked example lets the learner recognise whether the proposed function matches their intention.

The studio task writes a function record. Its fields include name, owner, purpose, input schema, output schema, data scope, side effects, permission conditions, completion evidence and version. Technical learners implement a small practice function. Other learners review the examples and test cases, supplying the meaning the code will need to preserve.

For the teaching-plan function, inputs might include the topic, learner context, selected source records and time available. Outputs might include a lesson sequence, practical task, support options and a review question. A source link accompanies each factual element. An absent input produces a question or an explicitly partial draft, according to the function's agreed behaviour.

The learner tests the record with three cases: a familiar topic, an unfamiliar topic with supplied sources and a case with conflicting preferences. The group examines whether the function returns a useful result and whether the review makes its choices understandable. A failed case becomes a correction to the function record and the relevant examples.

The life reflection asks which part of the service the learner wants to keep doing personally. Delegation may free attention for an important relationship, creative choice or civic judgement. The person identifies where they want assistance, where they want collaboration and where they want to make the decision themselves.

Teaching practice helps a peer define one desired function from their own interest. The trainee returns the purpose in the person's words before introducing the fields. Evidence includes the discovery notes, function record, three test cases, revision and peer feedback. The result is a capability with enough definition to support tomorrow's caller and later specialist agents.

Source: S09 Mixture of Experts Function Callers and AutoGen Agents.
